# Migrate PSMS to Postgres (Supabase) + Cloudinary + Vercel-compatible realtime

Approved by you last turn ("Yes, implement as planned"). Code only — placeholders + README for the Supabase/Cloudinary credentials you'll provision later. Re-presenting because the previous ExitPlanMode was rejected (blocking edits).

## Decisions (locked)
- **DB:** SQLite → **Supabase Postgres**
- **Files:** local `uploads/` disk → **Cloudinary** (direct browser upload)
- **Realtime chat:** retire the Socket.IO mini-service → **Supabase Realtime Broadcast**, keeping the existing HTTP messaging API for persistence
- **Existing data:** one-time migration script moves SQLite rows + uploaded files into Supabase + Cloudinary

Key finding: the main app **already** has full HTTP persistence for messaging (`/api/messages`, `/api/conversations`, `/api/contacts`) and the frontend already branches to an HTTP fallback. So the chat work is: standardize on HTTP persistence (already built) + replace the push layer with Supabase Realtime — not a rewrite.

## Implementation steps
1. **package.json:** add `cloudinary`, `@supabase/supabase-js`; remove `socket.io`, `socket.io-client`; add `postinstall: prisma generate`. Run `bun install`.
2. **prisma/schema.prisma:** `provider = "postgresql"`, add `directUrl = env("DIRECT_DATABASE_URL")`. Schema is already Postgres-safe (no model changes).
3. **.env.example (new):** `DATABASE_URL` (Supabase pooled 6543), `DIRECT_DATABASE_URL` (5432), `CLOUDINARY_*`, `SUPABASE_*`, `NEXTAUTH_SECRET`.
4. **src/lib/db.ts:** gate `log: ['query']` to non-production.
5. **src/lib/cloudinary.ts (new):** sign upload params, signed download URL (1h), destroy asset.
6. **src/lib/realtime.ts (new):** Supabase clients + `publishToUser(userId, event, payload)` + `subscribeUser(userId, handlers)` over per-user Broadcast channels.
7. **GET /api/documents/upload-url (new):** student-only gate; returns signed Cloudinary upload params + folder.
8. **POST /api/documents/upload (rewrite):** JSON `{title, description, documentType, isFinal, publicId, fileName, fileSize, fileType}` → creates `Document` with `filePath = publicId`. No disk I/O.
9. **GET /api/documents/[id]/download (rewrite):** role guard → 302 to signed Cloudinary URL.
10. **DELETE /api/documents/[id]:** `destroyAsset(publicId)` instead of `fs.unlink`.
11. **POST/GET /api/messages:** after create → publish `receive_message`; after mark-read → publish `messages_read`. Typing stays ephemeral via Broadcast.
12. **Delete src/lib/socket.ts; rewrite `use-socket` → `use-realtime`; rewrite socket-provider; rewire chat-window (always POST, drop socket branch) + chat-list listeners.**
13. **Update upload-document.tsx mutation:** 3-step direct browser upload.
14. **Remove `mini-services/chat-service/` + orphaned `/api/chat/wake` route.**
15. **Vercel housekeeping:** remove `output: "standalone"` from next.config.ts; strip ~60 `?XTransformPort=3000` query strings.
16. **README.md:** replace SQLite/local-file deployment with Supabase + Cloudinary + Vercel steps.
17. **scripts/migrate-to-supabase.ts (new):** read `prisma/db/custom.db`, insert rows into Postgres, upload each Document file to Cloudinary, store `public_id`. Idempotent.

## Security note (documented in README)
Supabase Broadcast channels (`user-{userId}`) are identified by name and subscribed with the anon key — not cryptographically private, matching the app's existing posture (authorization is enforced in the HTTP API, not the transport). Hardening via Supabase Realtime authorization tokens will be noted as a follow-up.
